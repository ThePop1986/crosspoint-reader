## D-001 · 2026-11-12 · Accepted
**Architecture A — Minimal CrossPoint Fork.** База — upstream CrossPoint 2.x (MIT), ветка `develop`, env `picco`. Folio — только референс UX/протокола.
*Why:* Picco уже поддержан upstream (PR #3947, `[env:picco]`, `partitions_picco.csv`, профиль в симуляторе). Folio — X4 Pro only, CrossPoint 1.6.5.

## D-006 · 2026-11-12 · Accepted

## D-008 · 2026-11-12 · Accepted (расширено D-019)
**Library layout не фиксирован.** Сравнительный тест в симуляторе 480×800. Корпус 50+ книг с длинными кириллическими названиями. Критерии: читаемость, частота листания, время рендера, память.

## D-009 · 2026-11-12 · Accepted
**Go/No-Go требует подтверждённого механизма восстановления**, а не только двух совпадающих бэкапов. Применимость процедуры восстановления проверяется для конкретной аппаратной ревизии без записи на устройство.

## D-010 · 2026-11-12 · Accepted
**KOReader Sync — исследовательская задача P2.** Интеграция с PiccoLink не считается готовой или спроектированной.
*Note:* upstream SCOPE.md закрыл новые сетевые коннекторы; KOReader document ID = MD5 имени файла или partial MD5 содержимого — нормализация EPUB меняет бинарный ID.

## D-011 · 2026-11-12 · Accepted
**PiccoLink: `DeviceRepository` + отдельный `CrossPointHttpAdapter`.** Domain/UI не знают об HTTP-эндпоинтах; адаптер версионируется по `/api/status`.

## D-012 · 2026-11-12 · Accepted
**Исходные EPUB не изменяются.** Нормализация — только на копиях; сохранять `dc:identifier`, имя файла и spine; проверять совместимость с сохранённым прогрессом.
*Evidence (код):* прогресс хранится в `/.crosspoint/epub_<hash(path)>/progress.bin` (spine + page); `clearBookCache()` удаляет весь каталог при upload-overwrite, rename и move (`src/network/CrossPointWebServer.cpp`).

## D-013 · 2026-11-12 · Accepted

## D-014 · 2026-11-12 · Accepted
**Результаты симулятора и железа разделяются.** Симулятор не доказывает аппаратную производительность, память, refresh, touch или энергопотребление. Каждая метрика помечается `SIM` или `HW`.

## D-015 · 2026-11-12 · Accepted (факт среды)
**Сборки прошивки — на машине владельца или в GitHub Actions.** В облачной среде Claude реестр тулчейнов PlatformIO недоступен; заявлять «собирается» можно только по логу реальной сборки.

## D-016 · 2026-11-12 · Accepted

Корректирует пункт «Upstream-first» из Audit v0.1. SD-theme система upstream — будущая точка миграции (R14).

## D-017 · 2026-11-12 · Accepted
**COVER_GRID — архитектурный и UX-референс, upstream-класс не меняется.** `CoverGridHomeUi` (`final`) подключается к HomeActivity через наш адаптер `HomeScreenUi` (Phase 0A report §8.2).

## D-018 · 2026-11-12 · Accepted
**PiccoLink никогда не перезаписывает книги на устройстве автоматически.** Политика загрузки по умолчанию — `FailIfExists`. Перезапись, переименование и перемещение — только по явному действию пользователя с предупреждением «прогресс чтения будет сброшен». Пакетные операции перезапись не включают.
*Evidence:* D-012.

## D-019 · 2026-11-12 · Accepted
**Сравниваются три варианта Library: A 3×3, B 2×3, C 3×2. Окончательного выбора нет.** Плюс контроль Home H0 — upstream COVER_GRID без изменений (Phase 0A report §8.4).

## D-021 · 2026-11-12 · Accepted (технический)

## D-022 · 2026-11-12 · Proposed (уточнено после ревью)
**Распространение прошивки = обязательства GPLv3.** Бинарник CrossPoint распространяется под GPLv3 (wolfSSL). CI по умолчанию **не публикует** `firmware.bin` (даже как artifact). Публикация — только вручную (`publish_firmware=true`), комплектом с `LICENSE`, `licenses/`, `PINS.md`, `SOURCE.txt`, срок хранения 7 дней. Наш код — MIT. PiccoLink — отдельная лицензия (рекомендация Apache-2.0 или MIT).

## D-024 · 2026-11-12 · Accepted (технический, по внешнему ревью)
**Сборки называем «прослеживаемыми», а не «воспроизводимыми», до первой зелёной сборки.** Точно закреплены исходники, actions (по SHA), тестовые инструменты (Pillow, epubcheck с sha256). Python-зависимости сборки и пакеты PlatformIO записываются в каждом запуске (artifacts `piccoos-env-*`); после первой зелёной сборки — перевести в constraints. Корпус детерминирован на Linux; на других ОС — Needs Verification.

## D-026 · 2026-11-12 · Accepted (технический, второе ревью)
**Все шаги CI выполняются с `shell: bash` (`-eo pipefail`).** Исправление ошибки v2: без явного `shell` GitHub не включает `pipefail`, и `cmd | tee` скрывал сбой. Скриншоты считаются действительными, только если созданы в текущем запуске; `home_cover_grid` проверяется глазами при первом прогоне. Публикация `firmware.bin` остаётся выключенной: `SOURCE.txt` не доказывает полноту Corresponding Source.

## D-027 · 2026-11-12 · Accepted (по первому CI, commit `c6372a68`)
**Сбой `simulator` вызван нашим скриптом, а не прошивкой или симулятором; прошивку не меняем.** В CI прошли `pins`, `corpus`, `firmware` (RAM 34.4%, Flash 35.9%), `unit-tests` и сборка `simulator_picco`. Шаг скриншотов упал: время в скрипте ввода симулятора абсолютное внутри сегмента (после каждого `WAIT`), а v3 трактовал его как задержку → `QUIT` раньше `SHOT`. Kit v4: абсолютные времена, `lint_script`, проверка строки `Saved screenshot`, размер 480×800; Library — кнопками `DOWN`→`ENTER`. Диагноз воспроизведён на заглушке с семантикой `HalGPIO.cpp` (v3 повторяет сбой CI один в один, v4 проходит); на реальном симуляторе — ждёт следующего запуска CI. COVER_GRID в CI применился (герой-карточка в `SCREEN`, миниатюры 130×218); строка «Using Lyra theme» для COVER_GRID — норма (общий `case` в `UITheme.cpp`).

## D-028 · 2026-11-12 · Accepted (по второму CI, commit `444e09c2`)
**Headless-скриншоты: `SDL_RENDER_DRIVER=software` в `capture_screens.sh`; прошивка, SDK и симулятор не меняются.** Второй запуск: тайминги v4 работают; Library открывается и кнопками (`DOWN`→`ENTER`, 1701 мс), и касанием `(0.50, 0.5225)` (1600 мс). Ни один `SHOT` не сохранён: симулятор (`HalDisplay.cpp:378`) создаёт рендерер с `SDL_RENDERER_ACCELERATED`, у драйвера `dummy` его нет → NULL → `presentIfNeeded()` выходит до `captureDueScreenshots()` без сообщения. Подтверждено на SDL 2.32.10: без подсказки — NULL, с подсказкой — рендерер `software`, снимок 480×800. В CI SDL 2.30.0 — подтвердит следующий запуск. Kit v4.1 = v4 Final + эта строка. Предложение upstream: логировать ошибку `SDL_CreateRenderer` в `HalDisplay::begin()` (не блокирует).

## D-029 · 2026-11-12 · Accepted
**Миниатюры обложек: две высоты — `thumb_300` (текущая книга) и `thumb_192` (недавние).** Одна `thumb_300` в слоте 128×192 показала бы центральные 64% обложки. Масштабирование при отрисовке исключено: дизеренный 1-bit при этом портится. Правило: в UI PiccoOS не больше двух высот обложек; сетка Library по возможности использует 192.

## D-030 · 2026-11-12 · Accepted
**Обложки: Fill по умолчанию; Fit для пропорций вне 0.55–0.80 — отложенная опция P2.** Fit требует правки `lib/Epub`: в 1-bit пути `crop=true` зашит жёстко. Её можно сделать только отдельным решением, после HW-измерений.

## D-031 · 2026-11-12 · Accepted
**Шрифты Home: только Noto Sans** — 18 bold (название), 16 (автор, процент, «Недавние»), 14 (подписи, панель, статус), 12 (заглушка обложки). Кириллица `0x400–0x4FF` проверена во всех кеглях; Ubuntu на Home не используется.

## D-033 · 2026-11-12 · Accepted

Интерфейс `HomeScreenUi` + тонкий `CoverGridHomeUiAdapter` (~40 строк, без логики): это меньшая правка `HomeActivity` (~20–25 строк), чем ветвление или изменение upstream-класса. Правки upstream ≤ 150 строк, с пометками `// PiccoOS:`.

## D-034 · 2026-11-12 · Accepted

## D-035 · 2026-11-12 · Accepted
**Выбор Home хранится в отдельном ключе `homeLayout`, а не как `uiTheme = 5`.** Upstream `3a5bfac` ограничивает enum (`clamp` → Lyra), но настройки на SD переживают откат, и поведение заводской прошивки Onyx неизвестно. С отдельным ключом `uiTheme` всегда валиден, а неизвестный ключ игнорируется. При пересохранении upstream удаляет ключ — после возврата Balanced нужно включить заново (допустимо). Убирает правки `UI_THEME` и `UITheme.cpp`. Совместимость с заводской прошивкой Onyx не подтверждена — задача Phase 0B.
