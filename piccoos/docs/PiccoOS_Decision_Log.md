## C-1 · 2026-11-13 · Accepted (уточняет Spec §3 «Пустые состояния», «Фокус и порядок»)
**Если книги есть, а истории чтения нет: карточка «Начните читать» / «Открыть библиотеку ›» — только касание, вне порядка фокуса.** Обложка текущей книги не рисуется, `thumb_300` не создаётся, процента и прогресс-бара нет. Начальный фокус («первый доступный элемент») — первая книга в нижнем ряду; при 0 книг — «Передача».
*Why:* при управлении кнопками полезнее сразу открыть книгу; Library доступна из нижней панели. Модель `selectorIndex` upstream (книги → меню) не нарушается — книжные индексы занимают только показанные книги.
*Consequence:* признак `hasContinueReading` используется согласованно в отрисовке, индексах фокуса, hit-test и `thumbHeightFor` (без текущей книги все миниатюры — 192, D-029).
*Уточнено 2026-11-13 (ревью v2, R1):* в фокус, Confirm, базу меню и генерацию миниатюр попадают **только видимые** книги (без истории — до 3, с историей — до 4). «Все книги ›» показывается по числу книг, найденных **до** сокращения списка (≥ 4), — при четырёх EPUB без истории ссылка видна. Правило «Начальный фокус „Передача“ при 0 книг» действует только для Balanced и только если не задан явный `initialMenuItem` (R5); upstream CoverGrid не меняется.

## C-2 · 2026-11-13 · Accepted (уточняет Spec §3 «Пустые состояния»)
**Без истории чтения нижний ряд называется «Новые книги» (en: «New books»), а не «Недавние».** Показываются до трёх последних добавленных книг, `thumb_192`, без полосок прогресса. Порядок — по дате добавления, если она есть в `LibraryIndexFile` (Spec §4 №6); иначе порядок индекса, факт фиксируется в логе.
*Why:* непрочитанные книги под заголовком «Недавние» вводят в заблуждение. Стоимость — одна строка i18n.
*Уточнено 2026-11-13 (ревью v2):* реализация использует upstream `SortOrder::RecentDesc` — это порядок по `modificationTime` файла (затем `firstSeen`, ordinal), а не по дате копирования на SD. Принято как приближение для A-07; файлы с сохранёнными при копировании timestamps могут идти не в порядке добавления.

## C-4 · 2026-11-13 · Accepted (толкование D-036, решение не меняется)
**D-036 относится к фактической ориентации отрисовки Home, а не к настройке ориентации Reader (`SETTINGS.orientation`).** Balanced не зависит от `SETTINGS.orientation`.
*Evidence (статический анализ, две независимые проверки — Claude Code и ChatGPT Work):* в текущих штатных путях Home рисуется в Portrait — `GfxRenderer.h:145` (начальная Portrait), `ReaderActivity.cpp:121` (сброс в Portrait в `onExit`), `XtcReaderActivity.cpp:62`, `SleepActivity`; временные повороты в темах восстанавливают ориентацию; `SETTINGS.orientation` применяется только в `ReaderUtils` (Reader). Достижимого пути, где Home рисуется в альбомной ориентации, не найдено.
*Consequence:* защитная проверка D-036 сейчас неактивна. Если появится реальный landscape-путь Home, проверка выполняется по фактической ориентации renderer (`renderer.getOrientation()`) — вместе с этим путём. Правка «BUG-D036» (`SETTINGS.orientation`) отменена.
*Не проверено:* runtime-roundtrip Library → Reader → Home. **Не считается выполненным тестом**; переносится в отдельный сценарий (A-08). Сценарий CI с альбомной настройкой Reader проверяет только то, что эта настройка не отключает Balanced.

## C-5 · 2026-11-13 · Proposed (A-08; в A-07 не реализуется)
**Ряд «Недавние» при наличии истории не дополняется непрочитанными книгами из библиотеки** (Spec §3: «Недавних меньше трёх — выравнивание влево, без заглушек»). Сейчас Balanced, как upstream CoverGrid, добивает ряд книгами из `LibraryIndexFile` (ревью v2, R6).
*Why:* непрочитанные книги под «Недавние» противоречат обоснованию C-2.
*Открыто:* как тогда определять показ «Все книги ›» (нужно общее число книг в библиотеке без лишнего чтения индекса). Решение — при проектировании A-08. До решения в A-07 сохраняется текущее поведение как известное отклонение.
