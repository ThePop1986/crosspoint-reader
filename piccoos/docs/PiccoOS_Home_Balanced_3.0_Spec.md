## 2. Решения

### D-029 Миниатюры: две высоты — 300 и 192
- Confirmed: `Epub::generateThumbBmp(h)` создаёт `thumb_<h>.bmp`. 1-bit; `JpegToBmpConverter` с `crop=true` масштабирует источник по **большему** коэффициенту под бокс `0.6h × h` и сохраняет изображение **целиком** (600×900 при h=300 → BMP 200×300). Обрезка — только при отрисовке: `BaseTheme::drawCoverThumbFill` рисует 1:1, по центру, с clip по слоту.
- `thumb_300` — текущая книга; `thumb_192` — недавние.
- Правило: в UI PiccoOS не больше двух высот обложек. Сетка Library в будущем по возможности использует 192.
- Масштабирование при отрисовке запрещено: дизеренный 1-bit при этом портится.

### D-030 Режим обложек: Fill
- v1 — Fill (поведение upstream). Fit для пропорций вне 0.55–0.80 — отложенная опция P2: она требует правки `lib/Epub`, где в 1-bit пути жёстко задан `crop=true`.

### D-031 Шрифты: только Noto Sans
- Confirmed: `NOTOSANS_12/14/16/18_FONT_ID` зарегистрированы в `src/main.cpp`, regular и bold; кириллица `0x400–0x4FF` есть во всех. Ubuntu UI_10/UI_12 на Home не используются.

### D-032 PSRAM необязательна
- Home работает без PSRAM: обложки рисуются из BMP с SD.
- Если `HalMemory::getPsramHeap().totalBytes > 0`, переиспользуется существующий `HomeCoverCache` (до 7 обложек; нужно 4). Новый кэш не пишется.

### D-033 Размещение кода и архитектура
- Confirmed: PlatformIO собирает `src/` (`simulator`: `build_src_filter = +<*>`). Корневой `piccoos/` не компилируется — там только инструменты и документы.
- Новый код — в `src/piccoos/`:

```
src/piccoos/home/HomeScreenUi.h             интерфейс экрана Home:
                                            begin, refreshCoverPaths, setSelection, selectedAction,
                                            thumbHeightFor(index), takeThumbHeightChanged, maxBooks, render
src/piccoos/home/CoverGridHomeUiAdapter.h   тонкая обёртка над upstream CoverGridHomeUi
                                            (~40 строк, только переадресация; upstream-класс не меняется)
src/piccoos/home/BalancedHomeUi.{h,cpp}     реализация Balanced 3.0
```

- Почему интерфейс и обёртка: Balanced нужны две высоты миниатюр, а `HomeActivity.cpp:172` запрашивает одну (`thumbHeightFor()` без индекса). Значит, `HomeActivity` всё равно правится. Интерфейс даёт ~20–25 строк правки против ~40–50 строк ветвления по 21 обращению к `coverGridUi` и не нарушает D-017.

### D-034 CI
- Новый обязательный сценарий `home_balanced`: `settings.json {"uiTheme":1,"homeLayout":1}`. Требования: кадр сохранён, 480×800, не пустой, заметно отличается от `home_lyra`.
- `home_lyra` и `home_cover_grid` остаются обязательными — регрессия upstream-тем.
- Экспериментальные сценарии на отдельных SD: 0 книг; книги без открытой.
- Первые кадры Balanced просматриваются глазами.

### D-035 Выбор Home — отдельный ключ `homeLayout`
- `homeLayout`: 0 — стандартный Home по `uiTheme`; 1 — PiccoOS Balanced. Загрузчик ограничивает значение числом подписей (механизм `clamp` upstream).
- PiccoOS никогда не записывает в `uiTheme` значения вне диапазона upstream. `uiTheme` задаёт стиль остальных экранов; по умолчанию Lyra.
- Откат на upstream: неизвестный ключ не читается (Confirmed: загрузчик обходит только реестр своих ключей), `uiTheme` валиден → обычный Home. При пересохранении upstream строит `settings.json` заново (`CrossPointSettings::toJson`) и `homeLayout` пропадает; после возврата на PiccoOS Balanced включается заново. Это допустимо.
- **Совместимость с заводской прошивкой Onyx не подтверждена** — проверить формат и путь её настроек по дампу в Phase 0B, без записи на устройство.

### D-036 Альбомная ориентация
- `homeLayout = 1` и портрет (`Portrait` или `PortraitInverted`) → Balanced.
- `homeLayout = 1` и альбомная ориентация → стандартный Home по `uiTheme` (Lyra), временно. Сохранённые `homeLayout` и `uiTheme` не меняются.

### D-037 Управление — штатная модель CrossPoint
- Новых назначений кнопок нет до проверки физического устройства.
- `NavNext` (Down) / `NavPrevious` (Up) — фокус; Confirm — открыть; Back на Home — последняя книга (поведение upstream); касание — открыть элемент.

### D-038 OPDS вне A-07
- В A-07 поддержка OPDS не добавляется и не меняется.
- Если пользователь настроил OPDS, upstream показывает его как пятый пункт меню (слот `PLUGINS`/`OPDS`). Balanced отображает этот пункт в нижней панели (5 ячеек × 96 px) без изменений логики.
- Место для OPDS в архитектуре Library резервируется при проектировании Library (источник книг наряду с SD), реализация — отдельный этап.

### Текст
- Перенос по словам; многоточие только в последней разрешённой строке.
- Слово шире колонки: разрыв с дефисом; если SDK этого не умеет — разрыв по символам без дефиса.
- Все строки — через `tr()` (ru/en).

### Заглушка обложки (нет обложки или ошибка генерации)
- Белый прямоугольник, контур 1 px.
- Название 14 bold по центру, до 4 строк (в слоте 128 — до 5 строк 12 bold); черта 40 px; автор 12 regular.

### Пустые состояния

| Состояние | Поведение |
|---|---|
| Нет книг | Вместо текущей книги — «Добавьте книги» и три способа: PiccoLink, Передача по Wi-Fi, microSD. Блока «Недавние» нет. Фокус — «Передача» |
| Книги есть, текущей нет | Карточка «Начните читать» + «Открыть библиотеку»; в «Недавних» — последние добавленные |
| Недавних меньше трёх | Выравнивание влево, без заглушек |

### Фокус и порядок
- Порядок = `selectorIndex` upstream: текущая → недавние 1–3 → Файлы → Библиотека → [слот OPDS/плагины] → Передача → Настройки.
- Начальный фокус — текущая книга; если её нет — первый доступный элемент.
- Касание: обложка или текст текущей книги, обложка или название недавней → открыть; ячейка панели → раздел; «Все книги ›» → Library.

### E-ink
- Вход на Home из книги — полное обновление. Сдвиг фокуса — перерисовка затронутых рамок или ячеек.
- Без серых заливок, теней и анимаций.
